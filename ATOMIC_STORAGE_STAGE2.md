# СЕТ · Этап 2 транзакционного хранения (лаборатория)

Дата: 2026-11-08
Статус: **ветка для испытаний, НЕ релиз**.
Опубликованный СЕТ продолжает работать на v1.3.12.
Исходная контрольная точка: checkpoint-2026-11-08-v1.3.12-pre-atomic-prototype.

## Сделано

- В тестовом режиме ?atomicLab=1 записи дневника сначала фиксируются в IndexedDB с ревизиями и атомарным compare-and-swap, затем обновляется совместимая копия localStorage.
- Для сохранения черновика и завершения тренировки успешное сообщение отображается только после подтверждения долговечной транзакции.
- Двойное нажатие «Закончить тренировку» не создаёт дублей в ожидании подтверждения.
- При переполненном хранилище старые копии не перезаписываются, показывается явная блокировка и доступ к скачиванию двух версий.
- При сбое зеркалирования после успешной IndexedDB транзакции следующая загрузка обнаруживает расхождение. Приложение ничего не сливает автоматически.
- Тестовая блокировка Web Locks исключает двух одновременно пишущих вкладок в лабораторном режиме.
- Журнал содержит максимум четыре предыдущие ревизии для каждого локального аккаунта.
- При незавершённых транзакциях браузер по возможности предупреждает перед закрытием вкладки (предупреждение beforeunload не гарантируется на мобильных платформах).
- Для будущей облачной интеграции добавлен барьер verifiedCloudPayload: блокирует передачу устаревшей или ещё не подтверждённой версии.
- В лабораторном режиме вход в аккаунт, облако и импорт отключены, чтобы не затрагивать реальные данные.

## Испытания

Запуск: http://127.0.0.1:18785/?atomicLab=1 на компьютере с работающим локальным сервером.

Автоматические проверки:
- задержанная IndexedDB транзакция: localStorage и сообщение «сохранено» не меняются до успешного завершения;
- искусственный QuotaExceededError: ни старое локальное содержимое, ни IndexedDB-копия не теряются;
- успешная IndexedDB транзакция + искусственная ошибка зеркала: обновлённая транзакционная копия сохраняется, обе версии доступны для экспорта;
- облачный шлюз ждёт записи и отвергает старое содержимое;
- реальные кнопки «Сохранить черновик» и «Закончить тренировку», ввод веса и повторений, попытка двойного завершения;
- конкурирующие вкладки, снимки, восстановление, экспорт PNG/PDF, графики прогресса;
- отсутствие сетевых запросов к боевому Supabase в лабораторном режиме.

**Ни одной операции записи в боевой Supabase не проводилось.** Прочитаны только метаданные SQL-функции. Она использует ревизию и блокировку записи на уровне PostgreSQL.

## Чего пока нет — не включать всем пользователям

Старая функция persist() по-прежнему имеет синхронный контракт для остальных действий — создания/изменения программы, выбора аккаунта и некоторых действий с историей. В лабораторном режиме эти вызовы ставят запись в очередь, но некоторые UI-подтверждения всё ещё могут прозвучать раньше транзакции.

Не подключены реальная авторизация, серверное восстановление и смена хранилища между аккаунтами. Нужны отдельные интеграционные тесты с фиктивными пользователями, явная обратимая миграция данных из localStorage и испытания на iOS Safari в PWA.

Это лабораторный промежуточный этап. **Не публиковать как v1.3.13 и не сливать с main** до завершения указанных проверок.
