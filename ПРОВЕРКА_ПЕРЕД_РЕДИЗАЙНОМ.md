# Проверка перед редизайном — v0.9.2

Пройдите проверки на опубликованном GitHub Pages после загрузки обновления. Не очищайте данные браузера и не удаляйте установленное приложение.

## 1. Синхронизация

- [ ] Войти в один аккаунт на телефоне.
- [ ] Изменить диапазон повторений у упражнения или добавить тестовую заметку, дождаться статуса «Все изменения сохранены в облаке» / «Дневник синхронизирован».
- [ ] Открыть тот же аккаунт на втором устройстве и убедиться, что изменение появилось.
- [ ] Удалить тестовую запись, если она не нужна.

## 2. Офлайн

- [ ] С открытым приложением включить авиарежим.
- [ ] Изменить повторения в незавершённой тренировке и убедиться, что приложение сообщает, что данные сохранены на устройстве и ждут отправки.
- [ ] Выключить авиарежим, подождать автоматическую синхронизацию.
- [ ] Убедиться, что статус изменился на сохранение в облаке и изменение видно на втором устройстве.
- [ ] По возможности повторить тест, закрыв приложение и запустив его без интернета, затем восстановить соединение без ручной очистки данных.

## 3. Облачные копии

- [ ] В разделе аккаунта открыть «Предыдущие сохранения».
- [ ] Убедиться, что список содержит даты сохранений.
- [ ] Создать тестовое изменение программы и дождаться его синхронизации.
- [ ] Выбрать прежнее сохранение и восстановить дневник.
- [ ] Убедиться, что прежние данные вернулись, а состояние до восстановления осталось среди облачных копий.

## 4. История и замена упражнения

- [ ] Записать тестовую тренировку и дождаться синхронизации.
- [ ] В другой программе заменить упражнение через библиотеку.
- [ ] Убедиться, что прошлые веса и повторы исходного упражнения остались в истории, а заменённое упражнение начинает отдельный прогресс.

## 5. Изоляция и восстановление

- [ ] Выйти из аккаунта и войти под другим тестовым пользователем: чужие программы и история не должны отображаться.
- [ ] Убедиться, что личные программы и история первого аккаунта возвращаются после входа обратно.
- [ ] Проверить, что скачанная резервная копия может быть импортирована обратно на тестовом профиле.

## Что уже проверено автоматически

- JavaScript проходит `node --check`.
- HTML не содержит дублирующихся ID и ссылки в JS на элементы интерфейса существуют.
- Все ресурсы из списка Service Worker найдены в пакете.
- Supabase: у таблиц `setlog_user_data` и `setlog_user_snapshots` включён RLS; функция `save_setlog_state` работает как SECURITY INVOKER; две текущие учётные записи имеют по одной облачной записи и по одной начальной копии.
- Security Advisor: нет предупреждений по таблицам и функции хранения; остаётся предупреждение Supabase Auth о защите от скомпрометированных паролей, недоступной в Free.

Полная проверка реального офлайна, email-потока и отображения интерфейса требует ручного прохождения списка выше после публикации. До этого не отмечайте релиз как полностью подтверждённый.
