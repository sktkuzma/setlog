# Отчёт проверки релиза v1.0.1

## Статические проверки
- JavaScript проверяется `node --check` для `app.js` и `sw.js`.
- Каталог упражнений разбирается как JSON; идентификаторы упражнений проверяются на уникальность.
- Все перечисленные в Service Worker локальные ресурсы должны присутствовать в корне релиза.
- Поиск по файлам релиза не должен находить старого имени библиотеки.
- Старые сохранённые значения с прежним именованием нормализуются к `coach` перед дальнейшим разбором, сохраняя совпадение ID в программах, каталоге, черновиках, истории и архиве замен.
- Проверяется наличие поля ссылки видео для варианта/замены, SVG-логотипов и соответствующих CSS-переопределений.

## Ручная проверка после публикации
1. Открыть Settings на телефоне и проверить единые интервалы карточек.
2. Открыть несколько упражнений с портретными и горизонтальными картинками; проверить, что изображения целиком помещаются.
3. Проверить компактность кнопки карандаша.
4. Открыть существующие ссылки Telegram и YouTube, проверить оформление и переход.
5. Для упражнения с вариантом добавить ссылку в поле «Ссылка на видео варианта / замены», сохранить, закрыть и открыть упражнение повторно — название варианта должно вести на нужное видео.
6. Войти в облачный аккаунт и проверить, что программы, история и синхронизация не изменились после миграции имен.
7. Проверить офлайн-открытие после обновления Service Worker.

Браузерные и сетевые сценарии с реальным Supabase требуют проверки на опубликованном сайте; они не помечаются как пройденные по одному статическому анализу.
