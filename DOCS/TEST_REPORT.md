# СЕТ 1.0.0 — отчёт проверок

Дата: 2026-10-28.

## Пройдено автоматически
- `node --check app.js` — успешно.
- `node --check sw.js` — успешно.
- HTML разобран; дублирующихся `id` не обнаружено.
- Статические обращения `$('#...')` проверены: все найденные ID присутствуют в HTML.
- Ресурсы, перечисленные в service worker, существуют в корне поставки.
- `manifest.webmanifest` корректен как JSON; иконки манифеста существуют.
- `exercise-library-tulupavel.json` разбирается; идентификаторы упражнений уникальны.
- Поле ссылки YouTube присутствует в редакторе; поле сохраняется в канонической записи упражнения и проверяется на домен YouTube/`youtu.be`.
- Новая запись тренировки формирует `setResults` отдельно по каждому подходу; код истории поддерживает новые результаты и старые записи без `setResults`.

## Изолированный UI smoke-test в Chromium — пройден
Страница запускалась в системном Chromium с подставленным локальным CSS/JS, тестовым состоянием schema v6 и заглушками хранилища/сети. Проверено:
- старый общий вес `80` перенесён в каждую строку подхода, повторы `10 / 8 / 7` сохранены;
- разные веса `60`, `70` и отдельные повторы принимаются; добавление подхода увеличивает количество строк; данные остаются после закрытия и повторного открытия карточки;
- подход можно отметить выполненным;
- пустая YouTube-кнопка выключена; ссылка из редактора активирует кнопку;
- новая история содержит отдельные результаты подходов и сохраняет число фактически заполненных строк; старая запись истории переживает миграцию;
- экран настроек и список программ отображаются;
- ошибок страницы и ошибок консоли нет.

Это тест пользовательского интерфейса на изолированной странице. В нём использовано временное in-memory хранилище и отключена сеть; тест не обращался к личным данным или к реальному аккаунту.

## Не проверено на реальном окружении
- опубликованный сайт и получение новой версии браузером/установленным PWA;
- Service Worker cache в установленном приложении;
- сохранение при реальной перезагрузке браузера и фактическая работа без сети;
- синхронизация с Supabase, повторная отправка после восстановления интернета и разделение данных двух аккаунтов.

Для этого нужна короткая проверка на опубликованном сайте по `RELEASE_TEST_PLAN_RU.md`.

- Приложение не было опубликовано этим процессом в GitHub; архив подготовлен для загрузки в существующий репозиторий.
- SQL Supabase не менялся; повторный запуск `supabase-setup.sql` не требуется для версии 1.0.0.
