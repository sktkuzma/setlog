# СЕТ — дневник тренировок

**Текущая версия: 1.3.7**

[Открыть приложение](https://sktkuzma.github.io/setlog/) · [Скачать последнюю версию](https://github.com/sktkuzma/setlog/releases/latest) · [История изменений](CHANGELOG_v1.3.7.md) · [Исходный код](https://github.com/sktkuzma/setlog)

СЕТ — веб-приложение для планирования силовых тренировок и ведения тренировочного дневника. Работает в браузере на телефоне и компьютере, поддерживает установку на домашний экран в формате PWA.

## Возможности

- **Программы и упражнения.** Готовые программы Full Body и Girls, собственные программы, редактирование тренировочных дней, порядок упражнений и библиотека упражнений.
- **Дневник.** Запись веса и повторений по каждому подходу, сохранение черновиков, история завершённых тренировок и редактирование прошлых записей.
- **Прогресс.** Сравнение рабочих весов, личные рекорды и аналитика по группам мышц.
- **Отчёты.** Выгрузка PNG и многостраничных PDF по тренировке или выбранному периоду.
- **Синхронизация.** Учётная запись и облачное хранение через Supabase при наличии подключения к сети. Локальная работа доступна и без входа.

Изображения упражнений и анатомические схемы служат иллюстрациями и не являются медицинскими рекомендациями.

## Начало работы

1. Откройте [СЕТ](https://sktkuzma.github.io/setlog/) в браузере.
2. Выберите программу или создайте собственную.
3. Запишите выполненные подходы и сохраните тренировку.
4. При необходимости создайте учётную запись для облачного хранения данных.

На поддерживаемых устройствах СЕТ можно установить как веб-приложение через меню браузера.

## Как сохраняются данные

Приложение использует локальное хранилище браузера. При авторизации СЕТ также синхронизирует дневник с облачной базой Supabase, когда доступна сеть. Локальные копии и облачная синхронизация не заменяют самостоятельного резервного копирования: очистка данных сайта, смена устройства или конфликт синхронизации могут привести к потере несинхронизированных записей.

**Рекомендуется регулярно скачивать резервную копию дневника через экспорт данных в настройках приложения.** Восстановление из JSON-файла заменяет текущий дневник после подтверждения. Перед импортом сохраните отдельную копию актуальных записей.

Если приложение сообщает, что дневник изменился в другой вкладке, обновите устаревшую вкладку перед продолжением. Не редактируйте один и тот же дневник одновременно в нескольких вкладках или на нескольких устройствах при отсутствии интернета.

## Обновления

Сайт публикуется через GitHub Pages из ветки `main`. Обычное обновление кода **не должно удалять** сохранённые дневники, черновики и пользовательские программы. Перед крупными обновлениями всё равно рекомендуется экспортировать данные.

Актуальная версия указана выше и в файле [`VERSION.txt`](VERSION.txt). Проверка в GitHub Actions сверяет обе записи и блокирует публикацию несогласованного изменения версии. Подробности последнего обновления — в [истории изменений](CHANGELOG_v1.3.7.md).

Контрольные точки исходного кода доступны в [ветках репозитория](https://github.com/sktkuzma/setlog/branches). **Восстановление предыдущей версии сайта не восстанавливает автоматически пользовательские записи** — для этого нужен ранее сохранённый экспорт дневника.

## Разработка и проверка

Проект использует JavaScript, HTML и CSS без обязательной сборки на клиенте. В репозитории есть проверки синтаксиса и регрессионные тесты, которые запускаются через GitHub Actions. Они проверяют основные сценарии сохранения, конфликтов и кеширования, но не заменяют тестирование интерфейса и экспорта на реальных устройствах.

Для локального просмотра достаточно статического HTTP-сервера. Не публикуйте секретные серверные ключи или личные резервные копии вместе с исходным кодом.
