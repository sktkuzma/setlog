# СЕТ — дневник тренировок 1.1.0

Мобильное PWA-приложение для записи фактически выполненных тренировок. Данные сохраняются на устройстве, а после входа в аккаунт синхронизируются с Supabase.

## Что нового в 1.1.0

- Разделены две операции: «Сохранить черновик» сохраняет незавершённую тренировку, а «Закончить тренировку» создаёт одну запись истории и начинает пустую сессию.
- Историческую тренировку можно доработать: исходная запись обновляется без дубликата, а незавершённый текущий черновик возвращается после сохранения или отмены.
- Незавершённая доработка истории хранится в отдельном локальном состоянии и восстанавливается после повторного открытия приложения.
- Убраны галочки выполнения подходов.
- В аналитике доступны только упражнения, у которых есть записи в истории.
- Service Worker обновлён до кэша v16, чтобы опубликованный браузер забрал новый код.
- В шаблоне `supabase-setup.sql` сохранено исправление неоднозначности `revision`. В рабочей базе оно уже применено; повторно запускать SQL для этого релиза не требуется.

## Как обновить GitHub Pages

1. Перед обновлением скачай резервную копию дневника из приложения.
2. Распакуй `SetLog_Update_v1.1.0.zip` и загрузи только перечисленные в архиве файлы в корень репозитория `sktkuzma/setlog`, заменяя одноимённые файлы.
3. Этот пакет намеренно не включает иллюстрации SVG/JPG/PNG и каталог упражнений: он не перезапишет новые иллюстрации, которые готовятся отдельно. `SHA256SUMS.txt` проверяет исходники и документацию, не включая изображения и каталоги.
4. Сделай коммит в `main` и дождись публикации GitHub Pages.
5. Пройди `DOCS/RELEASE_TEST_PLAN_RU.md`. Изолированный браузерный тест уже проверил логику черновика, доработки истории и возврата данных; синхронизацию на реальном сайте нужно подтвердить после публикации.

Контрольная точка предыдущей версии должна храниться отдельно и не перезаписываться. Для Supabase не требуется новая таблица, изменение схемы или повторный запуск миграции.
