# СЕТ · Атомарное сохранение, этап 4 (лабораторная интеграция)

Дата: 2026-11-08
Текущая рабочая версия GitHub Pages: **v1.3.12** (не изменяется).
Эта ветка **не является релизом**. Использовать только фиктивные дневники и локальный предпросмотр.

## Что реализовано

1. В рамках одного аккаунта основная запись дневника и отдельный черновик редактирования исторической тренировки находятся в одной транзакционной IndexedDB-записи с ревизией.
2. Ввод веса, повторений и заметок при доработке истории сначала записывается в IndexedDB. Затем обновляется совместимый локальный ключ `setlog-pwa-v1:history-edit-v1`.
3. При завершении доработки изменённая история и удаление её временного черновика входят в **одну** IndexedDB-транзакцию с проверкой ревизии. Ошибка сохраняет обе старые копии.
4. Отмена доработки подтверждается транзакцией перед удалением черновика из локального ключа.
5. Старые лабораторные записи IndexedDB, где ещё нет поля `historyEditRaw`, мигрируют без удаления исходной локальной копии. При расхождении копий автоматически ничего не заменяется.
6. На экране блокировки можно скачать локальный и транзакционный дневники; если присутствует черновик истории, доступны отдельные копии черновика.
7. Импорт JSON и восстановление из локальных снимков в тестовом режиме теперь используют подтверждение транзакции до уведомления об успехе, последовательно выполняются с остальными важными изменениями. Во время незавершённой доработки истории импорт запрещён.
8. Service worker обновлён на отдельную кеш-версию для тестовой сборки.

## Новые автоматические испытания

- Действительный ввод веса/повторов через интерфейс доработки старой тренировки.
- Задержка общей транзакции: история и черновик не меняются преждевременно.
- Успешное совместное сохранение истории и очистка черновика, затем перезапуск приложения.
- Отказ объединённой транзакции (симуляция QuotaExceededError): сохранённая история и черновик остаются прежними.
- Отмена доработки: черновик удаляется в обоих хранилищах, старая история остаётся.
- Миграция старой лабораторной записи IndexedDB без поля черновика.
- Импорт повреждённого JSON: отказ без изменений.
- Импорт исправной тестовой копии: успех после подтверждения транзакции.
- Откат после импорта к прежнему локальному снимку.
- Ошибка при импорте: старый дневник остаётся целым.
- Все прежние регрессионные тесты СЕТ (сохранение, история, PNG/PDF, Прогресс 2.0, offline, каталоги упражнений).

## Ограничения и запреты выпуска

- Облачная синхронизация реальных аккаунтов и автоматическая двусторонняя миграция **ещё не подключены к этому прототипу**. В лабораторном режиме Supabase и вход в аккаунт отключены.
- Печать и экспорт пользовательского JSON по-прежнему не включают отдельный незавершённый черновик истории: для него предусмотрено отдельное восстановление на аварийном экране.
- Некоторые высокочастотные изменения интерфейса ставятся в транзакционную очередь, но отдельные текстовые уведомления пока не подтверждают каждое нажатие. Перед выпуском требуется общий аудит всех операций.
- Нужно протестировать смену реального облачного аккаунта и конфликты двух устройств на фиктивных учётных записях, а также iPhone Safari PWA, принудительное закрытие приложения, ограничение памяти.
- Никакие данные пользователя, Supabase и опубликованный `main` не изменять до полного завершения проверок.
- Перед выпуском сохранить восстановительный ZIP и отдельно попросить пользователя экспортировать JSON настоящего дневника.
