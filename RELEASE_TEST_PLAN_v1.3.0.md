# План проверки релиза СЕТ v1.3.0

## Перед публикацией

1. Выполнить `node --check app.js` и `node --check sw.js`.
2. Проверить наличие всех 44 ресурсов, упомянутых в `sw.js`.
3. Проверить синтетическую историю для одной тренировки, периода из нескольких тренировок, упражнения с двумя взвешенными записями, упражнения с одной записью и упражнения без заполненного веса.
4. Создать PNG одной тренировки, PNG за период, PDF одной тренировки и PDF за период.
5. Проверить PNG 1200 × 1500 px; PDF должен открываться как многостраничный A4.
6. Убедиться, что в отчёты не включены калории и длительность нахождения в зале.

## После публикации на GitHub Pages

1. Сначала скачать резервную копию дневника.
2. Экспортировать PNG одной тренировки, открыть на телефоне и убедиться, что это карточка, а не длинное полотно текста.
3. Экспортировать PNG за период и сверить даты, тренировки, подходы, повторения, прирост и сумму повторений с историей.
4. Скачать PDF за период и проверить сводку, графики, рейтинги и журнал.
5. Экспортировать одну тренировку в PDF и проверить список упражнений и подходов.
6. Убедиться, что упражнение с одной записью не получает фиктивного показателя прироста.
7. Проверить экспорт, если часть подходов записана без веса или повторений: объём должен учитывать только полные пары вес × повторения.
8. Повторить скачивание в мобильном браузере и открыть оба формата.

## Ограничения

Браузерный тест выполнен с синтетическими данными в изолированной среде; реальную историю пользователя он не использовал. Схема Supabase не менялась, SQL запускать не нужно.
