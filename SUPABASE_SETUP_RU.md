**Проект уже создан и база настроена через подключение Supabase.** Эта инструкция нужна для завершения Auth и публикации клиента.

## Параметры проекта

- Project ref: `xikwzwqorwdhwhurzmlx`
- Project URL: `https://xikwzwqorwdhwhurzmlx.supabase.co`
- Регион: Северная Европа (`eu-north-1`)
- Тариф на момент создания: Free
- Таблица `public.setlog_user_data`: создана, RLS включён
- RPC `public.save_setlog_state(jsonb, bigint)`: создана как `SECURITY INVOKER`; RLS остаётся активным при вызове
- Security Advisor после настройки: предупреждений не обнаружено

Файл `supabase-config.js` в этом пакете уже заполнен Project URL и публичным publishable key. Publishable key предназначен для использования в браузере. **Не публикуй service_role/secret key, пароль базы данных или SMTP credentials.**

## 1. Auth URL Configuration

Открой [Auth → URL Configuration](https://supabase.com/dashboard/project/xikwzwqorwdhwhurzmlx/auth/url-configuration) и укажи:

- **Site URL:** `https://sktkuzma.github.io/setlog/`
- **Redirect URLs:** добавь `https://sktkuzma.github.io/setlog/`

В [Auth → Providers](https://supabase.com/dashboard/project/xikwzwqorwdhwhurzmlx/auth/providers) проверь, что Email включён и email confirmation включён. Приложение использует этот адрес для confirmation и сброса пароля.

## 2. Важное ограничение исходящей почты Supabase

Стандартный встроенный SMTP в Supabase предназначен для тестирования и по умолчанию **отправляет письма только на адреса, относящиеся к членам команды проекта/организации**. Поэтому твой адрес может сработать, а друзья могут не получить письмо подтверждения или сброса пароля.

Чтобы друзья могли регистрироваться с подтверждением email, настрой отдельный SMTP-провайдер в [Auth → SMTP Settings](https://supabase.com/dashboard/project/xikwzwqorwdhwhurzmlx/auth/smtp). Не добавляй друзей в команду Supabase только ради писем: членство в организации даёт доступ к панели управления, а не просто к приложению. Не отключай подтверждение email ради обхода проблемы без осознанного решения.

## 3. База данных

Схема уже применена в проекте и проверена. Файл `supabase-setup.sql` прилагается как воспроизводимая миграция и сделан идемпотентным для этой версии. Повторно запускать его сейчас не нужно. Он не удаляет пользовательские данные, но при дальнейших изменениях схемы сначала создай отдельную контрольную точку.

В таблице хранятся пользовательские данные отдельной строкой на `auth.users.id`. Политики SELECT/INSERT/UPDATE ограничивают доступ строкой, у которой `user_id = auth.uid()`. У роли `authenticated` нет разрешения DELETE. Функция сохранения работает как `SECURITY INVOKER`, не обходит RLS и проверяет ожидаемую ревизию.

## 4. Публикация GitHub Pages

1. Перед загрузкой экспортируй текущие тренировки из локального приложения в JSON.
2. Скачай `SetLog_Update_Supabase_Cloud_v0.9.1_Configured.zip` и распакуй его.
3. Загрузи все файлы из корня распакованного архива в корень репозитория `sktkuzma/setlog`, заменяя одноимённые файлы.
4. Выполни один `Commit changes` в ветку `main` и дождись публикации GitHub Pages.
5. Открой `https://sktkuzma.github.io/setlog/` онлайн, зайди в раздел аккаунта и зарегистрируй свой аккаунт.

## 5. Перенос локальной истории

Если на устройстве уже есть история, изменённые программы, пользовательские упражнения или картинки, приложение должно показать экран выбора источника. Для первого аккаунта выбери перенос локальных данных в облако, если именно эта локальная копия актуальна. Перед импортом обязательно сохрани JSON вне телефона.

Проверь, что после синхронизации сохранились обе программы, история, веса, повторы, картинки и ссылки. Затем открой приложение на втором устройстве и войди под тем же аккаунтом. Для проверки изоляции создай отдельный тестовый аккаунт и убедись, что он не видит данные первого.

## 6. Обязательные проверки перед использованием

- [ ] Site URL и Redirect URL указаны точно, включая завершающий `/`.
- [ ] Подтверждение email сработало (почтовый адрес разрешён SMTP-провайдером).
- [ ] Вход с верным паролем и отказ с неверным паролем проверены.
- [ ] Сброс пароля возвращается на сайт и позволяет задать новый пароль.
- [ ] Первый перенос локальной истории завершился без потерь.
- [ ] Запись, сделанная на одном устройстве, появляется на другом после синхронизации.
- [ ] Отключение сети показывает несинхронизированное состояние, а не ложное подтверждение облака.
- [ ] Два разных аккаунта не видят данные друг друга.
- [ ] Замена упражнения из каталога не уничтожает историю исходного упражнения.
- [ ] JSON-резервная копия сохранена вне телефона.

## 7. Резервные копии и Free

Free не заменяет независимую резервную копию базы. Сохраняй JSON из приложения и периодически выгружай данные облака отдельно. Не храни единственную копию данных только в телефоне или только в облаке.
